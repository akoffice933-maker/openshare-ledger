**Задание:** `tasks/review_2026-09.jsonl` — 60 извещений
**Объём:** 2–4 часа
**Срок:** до 30 сентября 2026
**Оплата:** points в публичном реестре (денежной стоимости не имеют — см. §9)

## 1. Суть

Мы строим корпус закупочной документации для обучения модели. Модели ещё нет, но есть базовая линия на правилах: она предсказывает категорию закупки по заголовку извещения и **ошибается в 53% случаев**.

Ваша работа — проверить её предсказания и исправить. Это не разметка с нуля: у каждого задания уже есть вариант системы, и вы либо подтверждаете его, либо ставите свой.

Почему это важно именно сейчас: в реестре один участник, и спор не применялся ни разу. Ваша разметка — первый случай, когда проверенная человеком работа попадает в леджер от второго человека.

## 2. Что нужно сделать

Открыть `tasks/review_2026-09.jsonl`. Каждая строка — одно извещение:

```json
{
  "notice_id": "2023105",
  "country": "IT",
  "title": "PROCEDURA APERTA PER LA FORNITURA DI 5 AUTOMEZZI...",
  "system_cpv": "34",
  "confidence": 0.21,
  "alternatives": [{"cpv": "50", "p": 0.14}, {"cpv": "42", "p": 0.11}]
}
```

| Поле | Что это |
|---|---|
| `title` | заголовок извещения на языке страны, **это вход** |
| `system_cpv` | предсказание системы, первые две цифры кода CPV |
| `confidence` | уверенность системы, от 0 до 1 |
| `alternatives` | два следующих варианта |

**Нужно проставить `human_cpv` — ваш код из двух цифр.**

Обратите внимание на `confidence`: у 44 заданий из 60 он ниже 0,35. Это значит, что система почти не уверена — и именно там ваша работа всего ценнее. Не пропускайте их.

## 4. Как решать

**Правило первое: по заголовку, а не по догадке.** Если из заголовка категория не выводится — так и пометьте (см. §5), не угадывайте. Нам нужна честная граница применимости, а не красивая цифра.

**Различие, на котором чаще всего ошибаются:**

| Пара | Как различать |
|---|---|
| 48 против 72 | 48 — поставить программу, 72 — услуги по её разработке и поддержке |
| 33 против 85 | 33 — оборудование и лекарства, 85 — услуги врачей и уход |
| 45 против 71 | 45 — строить, 71 — проектировать и надзирать |
| 34 против 50 | 34 — поставить машину, 50 — её чинить |
| 30 против 48 | 30 — железо, 48 — софт |

**Язык.** Корпус на 15 языках. Переводить заголовок необязательно, если вы понимаете его по ключевым словам: `mantenimiento` — обслуживание, `servicio` — услуга, `fourniture` — поставка, `dostawa` — поставка, `usługa` — услуга, ` Lieferung` — поставка. Слова-маркеры типа `servicio / usługa / entretien / świadczenie` почти всегда означают услуги, а `suministro / dostawa / fourniture / furnizare` — поставку товара.

**Если сомневаетесь** между двумя кодами — ставьте тот, что по заголовку вероятнее, и помечайте `unsure: true`. Сомнение, записанное честно, полезнее уверенной ошибки.

## 5. Формат ответа

Добавьте к каждой строке два поля и сохраните файл:

```json
{
  "notice_id": "2023105",
  "country": "IT",
  "title": "PROCEDURA APERTA...",
  "system_cpv": "34",
  "confidence": 0.21,
  "alternatives": [{"cpv":"50","p":0.14},{"cpv":"42","p":0.11}],
  "human_cpv": "34",
  "unsure": false,
  "note": "CIG 9454059849 — номер процедуры; компакторы для мусора"
}
```

| Поле | Обязательно | Что писать |
|---|---|---|
| `human_cpv` | да | две цифры из §3, либо `null` если неопределимо |
| `unsure` | да | `true`, если сомневаетесь |
| `note` | нет | почему выбрали иначе; на языке извещения или по-русски |

**Не меняйте** `title`, `notice_id`, `system_cpv`, `confidence`. Если исходные поля изменены, вклад не пройдёт проверку — система сверит их с corpus.

## 6. Подготовка окружения

### Подпишите коммиты

В реестре каждая запись хранит уровень доверия, и он берётся **из подписи git, а не из поля автора**. Подделать его нельзя: коммит с чужим именем в поле author всё равно останется неподписанным. Сейчас в леджере 14 записей и все неподписанные — ваша станет первой с подписью.

```bash
# ключ
gpg --quick-generate-key "Ваше Имя <ваш@email>" default default 1y
gpg --list-secret-keys --keyid-format=long

# сказать git
git config --global user.signingkey <ID_КЛЮЧА>
git config --global commit.gpgsign true
```

Проверка:

```bash
git log --pretty=format:'%h %G? %GK' -1
# G — подпись действительна; N — нет
```

Без `G` не отправляйте.

### Форк и ветка

```bash
git clone https://github.com/akoffice933-maker/openshare-ledger
cd openshare-ledger
git checkout -b review-2026-09
```

Положите файл в `tasks/review_2026-09.done.jsonl` — **новый файл**, исходный не трогайте.

## 7. Что нельзя

| Нельзя | Почему |
|---|---|
| Угадывать, если из заголовка не следует | нам нужна честная граница, а не завышенная точность |
| Менять `title` и `system_cpv` | система сверит с корпусом и отклонит вклад |
| Размечать по внешним данным | только по заголовку; корпус должен быть воспроизводим |
| Копировать чужие ответы | вклад атрибутируется, и это ваша подпись |
| Переписывать `system_cpv` в `human_cpv` | проверка считает долю совпадения на заданиях с низкой уверенностью; выше 95% — отклонение |
| Включать персональные данные в `note` | проверка на email, телефон, IBAN стоит в системе |
| Смешивать held-out | отложенный сет в репозитории не лежит; встретить его нельзя |

О справочных номерах: `CIG 9454059849` в итальянских извещениях — это номер процедуры, а не телефон. Система это уже знает, но в `note` лучше писать словами.

## 8. Как работа попадает в реестр

```
ваш коммит → collect → score → verify → snapshot → метка времени RFC 3161
```

Начисление считается по числу записей, прошедших проверку:

| Проверка | Что отсекает |
|---|---|
| Схема | нет `human_cpv`, пустые поля |
| Дубликаты | та же запись уже принята |
| Контаминация | запись совпала с отложенным сетом |
| Персональные данные | email, телефон, IBAN, номер карты |
| Подпись | уровень доверия из git |

Затем цикл запечатывается независимой меткой времени. Проверить результат можно самому:

```bash
python3 -m ledger verify --anchors
python3 -m ledger verify --recompute
python3 -m ledger selftest
```

Ваша запись останется в реестре навсегда вместе с вашим именем, подписью и оценкой. Леджер только дополняется: задним числом ничего не переписывается.
